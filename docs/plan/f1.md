# F1 tenant and identity foundation

The blueprint's next work package after F0 is **F1 — tenant and identity
foundation**: OIDC authentication, membership, personal postman registration,
device identities and RLS. Its exit gate is passing cross-tenant authorization
tests. The rows below are repository implementation slices, not additional
blueprint stages or evidence that F0 approvals are complete.

| Slice | Status | Required result |
| --- | --- | --- |
| F1.1 Provider-neutral token authentication | Implemented; provider rollout pending | [JWT access-token validation](../security/oidc-authentication.md), HTTPS discovery/JWKS, exact issuer/audience, negative tests and no implicit tenant authority |
| F1.2 Tenant membership and personal postman persistence | Implemented; production integration pending | Migrations, separate runtime/provisioning roles, active membership lookup by verified issuer/subject, immutable local identities, one primary postman, transaction-local RLS and actual pool tests |
| F1.3 Provisioning and owner access | Implemented subset; production rollout pending | Audited platform provisioning, explicit verified membership selection, operation scopes and object grants, owner-only postman access; no arbitrary tenant header authority |
| F1.4 Device identity enrollment | In progress: WebAuthn design, verifier experiment and staged contracts; application enrollment pending | Proof of possession and step-up binding, one active device, replacement/revocation concurrency and retained attribution |
| F1.5 Integrated authorization acceptance | Pending | Real application API/worker/role/pool negative tests across two tenants and multiple users; current membership and device revocation checks |

F1.1 authenticates an external caller; it does not create a tenant/user/postman,
resolve membership, authorize tenant data, select a provider, or implement client
login/token acquisition. Its default and fallback authorization policies deny
application access until explicit operation policies are implemented. Test-only
probe routes are not deployed Gateway endpoints.

F1.2 implements the [identity persistence library](../security/identity-persistence.md)
and actual PostgreSQL role/pool tests. F1.3 adds [separate provisioning and owner APIs](../security/provisioning-owner-access.md)
with current grants, scoped selection, audit/replay atomicity and explicit budgets.
The APIs are disabled by default. Policy updates, audit queries and device/worker
integration remain later work.

F1.4 starts with the [E02 review packet](../security/device-enrollment-review.md)
and opt-in signed step-up evidence. The [credential design](../security/enrollment-credential-design.md)
selects WebAuthn registration plus assertion, supported by an isolated pinned
verifier experiment. The [staged HTTP contract](../protocols/device-enrollment.md)
now defines enrollment/revocation schemas, replay, expiry and proof order with
executable contract checks; persistence, grant administration and opt-in API
integration are next. First-contact/replacement UX, messaging-key binding,
client-distribution trust and independent review remain open.
There is no device enrollment endpoint or persistence yet. The packet records
decisions and acceptance tests needed before those are built.
The maintainer selected one active logical device identity (no hardware or key
non-copyability guarantee) and mandatory independent verification before sending,
including after key replacement. The credential profile is specified; messaging
credential/proof binding remains a separate review before messaging activation.

F0 architecture/threat/crypto/contract review gates remain open. ADRs remain
Proposed. The user selected provider-neutral integration with explicit issuer and
audience configuration; that choice does not approve a production provider,
provisioning model or device credential format.

[Native checks N01/N02](../security/agent-safety.md#pending-native-checks) and
[production integration P01–P03](../../tests/Harness/README.md#evidence-and-scope)
remain pending. The F0.5 SQL/JetStream fixture is not the F1 application schema.
P01 includes actual F1.3 API/role/pool subset evidence but remains open for device,
worker/routing integration, deployment and production failure modes. Dependabot #10 remains deferred; crypto pins are unchanged.
